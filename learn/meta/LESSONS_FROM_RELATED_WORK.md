# 相关工作的经验与对本方案的分析（2026-09-29，文献精读工作流；末尾 CHECK 部分是核查代理的更正，优先于正文）

# SUMMARY
总的结论：文献支持我们方案的主干，暴露出的主要问题在数据和训练目标上，不在网络结构上。

文献支持的部分有五点。第一，用随机误差算子的合成先验训练，输出后验预测分布。第二，只看本船自己的状态、指令和误差历史（D6）。第三，任务码 c 按"对预测有用"来定义，用捐赠段（同一个误差算子作用在其它回合的航行片段上）做"换个计划会怎样"的反事实目标。第四，解码器对 c 是非线性的（FiLM）。第五，用两个条件流一次生成整段轨迹，MPC 里每条样本的 c 贯穿整条计划。这些都有直接证据：PFN、Forgione、Balim、RMA、Neural-Fly、Rufolo、Mamba4Cast、D-MPC、PETS、CSDI。

我对照读了代码（model2.py、data2.py、control/mpc.py），文献暴露出四个具体问题。
(1) 训练集是固定的小集合：约 2.5 万个检查点，每个检查点有一个 c 目标和一条 nu 轨迹，B 段要把它们各看约 75 遍。同类工作每一步都抽新系统，量级是千万级。PFN"不会过拟合、自动校准"的论证，只在一直有新数据时成立。
(2) 捐赠段标签是"开环"算的。本算子的规则被放在捐赠回合录下来的状态上计算，它自己造成的误差没有反过来推动船。MPC 要问的恰恰是"按这个计划开，误差把船推偏以后又会怎样"。而且现有的反事实指标用的也是同样的开环标签，所以看不出这个偏差。
(3) 预测器只训练到 20 步，MPC 视界是 24 步。
(4) 训练用的指令来自随机机动，部署时来自 MPPI 和探测策略，这是文献里多次出现的输入分布偏移。

建议按性价比排：
- 先对齐视界；
- 做一次数据规模诊断，然后改成分轮次生成新数据（保留两段式训练，新数据的 c* 用已有的 fit_codes 拟合）；
- 在 lofi 里带着本算子从捐赠段起点重跑，得到闭环的捐赠标签；同一套重跑程序顺便给每个检查点生成多条噪声续写，供 nu 流训练；
- 评估里补上：联合评分、只对"可预测部分"算的技能、闭环 MPC 代价；
- 然后补传感器伪影、按窗口的稳健缩放、更长的回合、MPC 在环数据，以及少量通用的先验成分（回合内突变、状态切换）。
- 后续阶段：探测奖励改用"不同 c 样本预测的分歧"而不是 c 的熵；实时路径用少步流、共享 c 样本；目标上的在线学习先做 c 的梯度精修，再做在仿真里就学会"便于被适配"的低维适配器。

最后，零样本的 C 组明显差于 A 组，在文献里是常态：没有一篇论文展示过零样本 sim-to-real 成功。遇到这种情况应先诊断数据覆盖和目标定义，而不是换成上限更低的模型。
# CONFIRMATIONS
- 路线本身：用随机算子的合成先验训练、输出后验预测，是 PFN（训练损失等于到真后验的期望 KL）、Forgione 2023（随机 LTI/WH 类）、TempoPFN、Chronos-2-Synth 都验证过的路线；纯合成训练可行。
- D6（只用本船状态、指令、误差历史）：Balim 2023 显示只看历史的 transformer 能追平知道真模型的卡尔曼滤波，并学会有色噪声的规律；Neural-Fly 全程无风速传感器、只从残差推断风况；CAPTURE 以'仿真与实测之差'作提示。三者都支持'看不见的持续原因会显现在误差历史里'。对突发原因的限制见风险。
- c 按'对预测有用'定义、不去回归算子参数：RMA 把 17 个环境参数压成 8 维 z，成功率 73.5%，直接估参数的 SysID 只有 56.5%。所以不应加'恢复算子参数'的损失。
- 捐赠段重标注：Rufolo 2025 的上下文段和查询段来自同一系统的不同序列，这让模型能回答'换一组输入会怎样'，也就是 MPPI 要问的反事实，是我们捐赠段的同一原则。Neural-Fly 的 DAIML 说明，网络会借输入分布偷偷记住环境；捐赠段迫使算子信息只能进入 c，在结构上解决了同一问题，论文里应明确点出。
- 解码器对 c 非线性（FiLM），线性-in-c 只作基线：D-MPC 把多步生成模型换成多步 MLP 后，得分从 65.98 降到 50.01；ALPaCA 的线性末层容量有限。32 维 c 与 ALPaCA 够用的 16-32 个特征同量级。
- 用流而不是高斯头：PFN 中灵活的分箱输出明显胜过高斯；Rufolo 2026 的高斯（Laplace）后验表示不了多峰，而迟滞系统恰好多峰，正对应我们的 B 组继电器；Rufolo 2025 的逐步独立高斯给不出前后相关的样本轨迹，没法配合 MPPI 的公共随机数。
- nu 一次生成整段 20x5、不逐步自回归：Mamba4Cast 一次出全视界的 MASE 为 1.153，自回归为 2.044；D-MPC 的整段生成累积误差更小；TimeGrad 逐步生成要 20 x N 次去噪调用。我们的 nu 流在时间上用注意力，每个 token 里含 5 个通道，同时混合了时间和通道两个方向，这正是 CSDI 消融中两个方向都重要的结论。
- 条件训练（历史、c、计划作直接输入），而不是采样时再引导：CSDI 的 CRPS 为 0.238，对照 0.360；TSFlow 的条件版既更好，也快约 3 倍。
- MPC 中每条样本的 c 贯穿整条计划、nu 作逐步随机：这就是 PETS 的 TS-infinity 和 ALPaCA'每条轨迹抽一次权重'的做法。PETS 表明粒子式传播比高斯矩匹配稳，不应改成高斯近似。
- 用算子的规则部分（无噪声）作 D(c) 的监督目标：ForecastPFN 在无噪声未来值上计损失，验证 MSE 从 33.1 降到 22.7；nu 流仍在含噪的 nu* 上训练，这是对的。
- 代码里已做对、并有文献支持的细节：B 段历史长度随机截取，含 25% 的极短历史（model2.py train_posterior），对应 ALPaCA 算法 1；观测噪声按回合抽对数均匀水平（obs_noise_sd），方向与 Forgione、Balim 一致；A 段按每个检查点的幅度做相对误差加权，与 ForecastPFN 稳健缩放同一精神；evaluate 里已有持续性基线（最近 4 个误差的平均）、尾部 Brier、90% 覆盖率、留出捐赠段上的反事实技能和 oracle 码。
- 视界上给解码器的是孪生模型在计划下的名义滚动（XH，不含未来波浪），属于 TFT 所说的'已知未来输入'，真实未来状态没有泄漏进输入。计算上也符合 Forgione 的速度结论：编码器和 c 后验每个控制步只跑一次，只有解码器和 nu 流需要对每条计划跑。
- 误差只注入 5 个速度方程，与 Hewing 2020 的选择矩阵结构一致。我们的船是欠驱动的（横荡、垂荡、纵摇没有直接执行机构），Richards 2021 和 Neural-Fly 那种'即时抵消'式自适应控制对这些通道无效，这说明'预测整个视界的误差、交给 MPC 规划'的路线是必要的，可写进论文的定位部分。
# RISKS
- [high] 训练数据是固定的小集合，会被记住。5000 回合，每回合约 5 个检查点（第 60、120、…、300 步），合计约 2.5 万个 c* 目标和 2.5 万条 nu 轨迹。A 段每个 c* 只被更新约 40 次（20000 步 x 48）；B 段 15000 步 x 128，每个检查点要看约 75 遍。PFN'不会过拟合、训练越久越校准'的论证，前提是每步都有新样本。结果可能是 A 组看着尚可，校准和 C 组却差，而且容易被误判为容量不足。 (from: PFN Sec.3 Corollary 1.1 与 Fig.4a；Forgione 2023 Remark 1（约 1e7-2e8 个新系统）；Rufolo 2026 Sec.IV-C（2560 万条）；Mamba4Cast Sec.4.1（从不重复，约 2700 万条）；代码 C:\Users\Administrator\Documents\usv-rl-mpc\learn\meta\model2.py（train_decoder、train_posterior、train_all 的步数和批量）、data2.py（CK0=60）)
- [high] 捐赠段标签是开环的。data2.py 的 _targets_one 把本算子的规则放在捐赠回合录下来的状态（XS、S）上计算，push_response 也从这些录下的状态出发。这些状态是被捐赠回合自己的算子和海浪推出来的，本算子的误差没有反过来改变船。c* 只在捐赠段 1-9 上拟合，自身未来（真正闭合的那一段）不进 c 拟合，于是'误差推偏船、船又改变误差'这一环整体掉进了 nu*，还混入了与 c 无关的捐赠方自身偏差。MPC 问的正是这一环。Hewing 指出，切断误差与状态的相关，会让预测过度保守或过度自信，取决于相关的符号。PRIOR_DERIVATION 的 RISKS 自己要求重标注窗口不超过 50%，而对 c 拟合来说现在是 100%。更麻烦的是，留出捐赠段上的反事实技能用的也是同样的开环标签，所以看不出这个偏差。 (from: Hewing 2020 Sec.III-B2(a) 与 Fig.2；Rufolo 2025 Sec.3.2（查询段是同一系统的真实模拟）；代码 C:\Users\Administrator\Documents\usv-rl-mpc\learn\meta\data2.py（_targets_one、push_response）、PRIOR_DERIVATION.md RISKS 中'Relabelled windows ... at most 50%'一条)
- [high] 闭环指令分布偏移。训练指令是随机航速/航向目标加 OU 抖动，四分之一回合是稳态。部署时指令由 MPPI 和后来的 RL 探测给出：变化频繁、常贴饱和，而且通过反馈与 c、nu 样本相关。只换输入信号，同一系统类的误差就可能翻 2.4 倍，所以 A 组技能会高估闭环里的真实表现。 (from: Rufolo 2025 Sec.4.4（PRBS 使 RMSE 达 0.309，约 2.4 倍）；RMA Sec.III-B（历史模块按策略自身分布训练）；Nagabandi 2019 Algorithm 1（带适应的 MPC 在环采集）；Moroncelli 2026 Fig.3（确定性模型在高频激励下明显变差）)
- [medium] 视界不一致。预测器 H=20（model2.py 第 52 行），MPC 默认 horizon=24（control/mpc.py 第 81 行），第 21-24 步没有训练过的误差预测。若把 20 步预测自回归拼接下去，又会丢掉整段生成的优势。 (from: Nagabandi 2019 Sec.5（规划视界应短于适应视界）；Mamba4Cast App.D（自回归拼接放大误差）；代码 C:\Users\Administrator\Documents\usv-rl-mpc\learn\meta\model2.py、C:\Users\Administrator\Documents\usv-rl-mpc\control\mpc.py)
- [medium] nu 流的数据特别薄，事件样本稀少。nu 流只在每个检查点的一条自身未来上训练，约 2.5 万条样本去学一个 100 维的条件分布。PRIOR_DERIVATION 的 D4 原本计划'同一算子、不同噪声种子的多条续写'，还没有实现。阈值事件每回合只以 0.5 的概率出现，20 步窗口里有事件的更少，所以尾部 Brier 会既不准又噪。再加上约四分之一的稳态回合和弱算子，安静样本在损失里占主导。 (from: Ziegler 2024 Sec.4（按总变差分箱、降采样拥挤箱）；PFN Sec.3（新样本越多越校准）；代码 C:\Users\Administrator\Documents\usv-rl-mpc\learn\meta\model2.py train_posterior（y1 只来自 m=0）、PRIOR_DERIVATION.md D4)
- [medium] c* 可能没有收敛，或者含有无关、不可辨识的方向。c-flow 学的是去拟合这些 c* 点，而不是按'看了这么多历史后对未来误差预测得好不好'端到端训练的，结构上接近 ALPaCA 的'no meta'对照组：方差照样随数据收窄，均值却是错的。无关方向上的随机值会被 c-flow 学成假的认知不确定性，之后探测奖励就会去追它。 (from: ALPaCA Sec.4.2 Algorithm 1 与 Sec.6.1、Fig.2-3；Rufolo 2026 Sec.II-B（摊销编码器只作精修的起点）；PRIOR_DERIVATION.md RISKS 中'Non-identifiability ... near-flat directions in z')
- [medium] D6 对突发原因反应滞后。只看本体状态的推断要等事件发生后才能察觉；对规划艇来说，砰击和浪击正是最要紧的事件，会集中表现在 heave/pitch 的前几步和尾部。此外，有波变体（仅 15% 训练样本关波）和主变体（100% 关波）是两个分别训练的网络，两者的差距里混进了训练随机性。 (from: RMA Sec.VI（下楼梯突然跌落导致失败，作者结论是需要外部感知）；Marlantes 2024（修正网络以波高为输入）；Chronos-2 Sec.4.2 与 Sec.5.2（已知协变量的收益最大）；代码 model2.py train_all（pw=1.0 对比 0.15）)
- [medium] 陈旧历史与突变。先验里只有慢漂移和阈值事件，没有回合内的算子突跳，编码器没学过何时丢弃旧历史。海况、载荷、纵倾一旦突变，最多一分钟的陈旧历史会拖慢恢复。 (from: Balim 2023 Sec.III-A、Fig.2c（切换系统后的恢复比初始适应慢）；ALPaCA App.A.3（时变参数要靠遗忘）)
- [medium] 长历史在训练中稀少。检查点在第 60/120/180/240/300 步，只有后两个能给满 250 个 token，历史长度又是均匀抽的，所以 150-250 步的历史占比很小；而实船航行时历史总是满的。Forgione 的 WH 类要约 200 步误差才稳定，我们的类更难。 (from: CAPTURE Sec.VII-B、Fig.8（对训练时的上下文长度过拟合）；Forgione 2023 Fig.3（LTI 约 20 步，WH 约 200 步）；Rufolo 2025 Table 1（上下文越长越好，直到噪声底）；代码 data2.py（CK0=60，T_EP 约 90 s）)
- [medium] 观测噪声模型太干净。obs_noise_sd 只有白噪声，水平为 A_REF 的 0.1%-3%，没有重尾、掉包、量化、饱和截断和时间抖动。实船由 IMU/GNSS 差分得到的一步误差，噪声可能超出这个范围。transformer 在噪声变大时比结构化拟合退化得更快，而且测试噪声高于训练范围时更差。 (from: Forgione 2023 Table 3（WH：sigma 从 0 到 0.5，RMSE 从 0.112 到 0.703）；Balim 2023 Fig.4-5；TempoPFN Sec.3.3（增强使 CRPS 改善 5.4%）；代码 model2.py obs_noise_sd)
- [medium] 尺度迁移。编码器的误差 token 用全局 e_sd 归一化再取 asinh，没有按窗口做稳健缩放。C 组和实船的误差量级会不同，输入可能落到训练范围外，被大值淹没的小模式也会丢。 (from: Chronos-2 Sec.3.1 Eq.1（按上下文标准化后取 asinh）；ForecastPFN Fig.5（稳健缩放优于最小-最大缩放）；代码 model2.py history_tokens)
- [medium] 认知不确定性只来自 c 的后验，缺少'网络本身不懂'这一类。流模型在分布外可能给出极窄的分布；连续可逆的 ODE 采样又可能把阈值事件那种'近零加远处尖峰'的形状抹平。直接用流的密度作 OOD 度量也不可靠。 (from: PETS App.A.1（分布外方差坍缩或爆炸）与 Sec.5.1；TimeGrad Sec.4.3 与 Sec.6（连续映射在模之间抹质量；似然会给分布外数据更高的值）)
- [medium] 探测奖励设计不当。如果奖励是'c 的熵下降'，船会为 c 里对代价无影响或不可辨识的方向（c* 不唯一）做无谓机动；如果用总方差，里面含 nu，船会跑去海况大、噪声大的地方'找信息'。 (from: PETS Sec.5.1（分不开两类不确定性时，探索会追逐不可减的随机性）；Richards 2021 Sec.III（只需学到影响跟踪的那部分）)
- [medium] 实时性。predict 用 32 个 c 样本 x 4 个 nu 样本，每个流 24 个 ODE 步。若对 128-192 条计划各采一遍 nu，在 16 GB 笔记本上、240 ms 之内很可能跑不完：D-MPC 在 A100 上 64 个样本就要约 93 ms。 (from: D-MPC App.J Table 7；Moroncelli 2026 Sec.III（热启动 + 5 步约 40 ms）；TimeGrad Fig.3 与 CSDI App.F.4（步数和样本数都有平坦区）；代码 model2.py predict)
- [medium] 指标只有逐通道、逐步的边缘量（技能、覆盖、CRPS、尾部 Brier），MPPI 用的却是整条 20x5 联合轨迹。通道之间（surge、heave、pitch 耦合）或前后步之间的相关错了，这些指标都看不出来；尾部也只检查了一个水平。 (from: TimeGrad Sec.4.1（CRPS-sum）；CSDI App.F.1；Chronos-2 Sec.3.2（加入 0.01 和 0.99 分位）)
- [low] 开环散布高估不确定性，让 MPC 变'胆小'。MPPI 评估开环指令序列，c 和 nu 的散布在 24 步上开环累积，而真船每 0.24 s 就重新规划一次。风险项若直接用视界末端的散布，会过度保守。 (from: Hewing 2020 Sec.III-A、Fig.1，以及 Sec.V-B（30 步视界只收紧前 20 步）)
- [medium] 在线适配器如果只在部署时才加上，就相当于 Nagabandi 的 MB+DE，适应慢；小数据微调能恢复的也有限。Piga 2024 没给具体数字，也没和从头训练比较，不能拿来作'少量实船数据就够'的依据。 (from: Nagabandi 2019 Sec.6.3、Fig.5；D-MPC Sec.4.3、Table 3a（22.74 升到 30.65，原始为 76.21）；Piga 2024 Sec.4.2)

# RECOMMENDATIONS

# EXPERIMENTS
- 数据规模诊断（最先做）：A 段固定，分别用 1/4、1/2 和全部约 2.5 万个检查点训练 B 段。报告训练集与新抽回合上的 c-flow/nu-flow 损失，以及 A 组的 CRPS、90% 覆盖和留出捐赠段上的反事实技能。若各项仍随数据量上升，就转向分轮次生成新数据。一次只跑一个训练进程。
- 开环与闭环捐赠标签的差别：随机取几百个检查点，两种标签都算，按通道报告二者之差的均方占标签方差的比例，并按算子强度分组看。比例大就执行闭环重标注。
- 视界：H=24-30 热启动微调后，看第 21-24 步的技能和覆盖是否与前面各步平滑衔接。
- 历史长度曲线（0/8/32/64/120/240）在 A、B、C 三组上：技能（分别对可预测部分和对观测误差）、覆盖、CRPS、1%/99% 尾部，同时画 c 后验散布和预测散布，二者应单调收窄。看曲线到 250 时是否仍在上升。在短历史一端比较'用 c 样本滚动'和'用后验均值 c 滚动'的 CRPS 与覆盖；按 PFN 的结果，短历史时前者的优势应最大。
- 激励与后验宽度：稳态回合与带抖动回合的 c 后验宽度对比，以及激励开始后后验是否收窄。这是 RL 探测奖励成立的前提。同时在 B 组（继电器）的短历史和稳态段检查 c 后验是否出现多峰，并且仍覆盖真值。
- 编码器是否'从状态分布猜算子'：拿同一个算子作用在不同海况、不同航速的捐赠输入上（规则部分加噪声样本）构造几段历史，c 后验应集中到同一处；若随海况或航速漂移，说明信息泄漏进了编码器。
- 突变恢复：在测试回合中途换算子，报告技能随'距切换时间'的变化。
- 先验成分留一法（TempoPFN 做法，小规模、逐个顺序跑）：每次去掉一种成分（事件、漂移、突发、双线性项、有色重尾噪声）重训，在 C 组上打分，看哪些成分真正覆盖了真实差距。同时做模型无关的覆盖检查：在 C 组误差序列上算描述统计（自相关、谱形、尾部指数、尖峰率、状态相关波动），看是否落在合成数据的统计云里。
- 闭环 MPC 代价：在同一个 MPPI 下，比较零误差模型、oracle c 和我们的模型在 A、B、C 三组上的闭环代价，并据此挑选检查点。另外比较'只加均值修正 D(c)'与'采样 c 和 nu'两种滚动的代价统计与真实结果；再比较开环预测散布与闭环实际散布的差距。
- nu 流采样预算扫描：ODE 步数取 4/8/16/24，每条计划的样本数取 4/8/16/32，记录 CRPS、覆盖、尾部 Brier、MPPI 代价估计的方差和耗时，取拐点。另对比 nu 样本与 nu* 的步间增量方差或功率谱，排查高频抖动。
- 噪声外推测试组：观测噪声高于训练范围时，c 后验应当变宽，而不是塌缩。
- 后续阶段：在 C 组上画适配收益随目标数据量的曲线（例如 5 分钟、20 分钟、1 小时、3 小时），比较'只用上下文'、'c 梯度精修'和'低维适配器'三者，据此决定 VM18 要采集多少数据。

- 确认 7：「nu 流每个 token 含 5 个通道，同时混合了时间和通道两个方向，正是 CSDI 消融的结论」: 说得过满。CSDI 的做法是每个 (时间, 特征) 格子一个 token，时间和特征两个方向各做一次注意力。它的消融没测过「5 个通道压进同一个 token」。我们的设计确实混合了通道（在 token 的线性层和前馈层里），5 个通道这样做很常见，但 CSDI 不能算直接证据。 -> 改成：CSDI 表明两个方向都要混合；我们在 token 内部混合通道，是另一种实现，CSDI 没测过。够不够用，由建议 4 里的联合评分（能量分数）来检验。
