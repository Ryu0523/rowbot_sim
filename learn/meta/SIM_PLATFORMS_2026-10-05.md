# LOTUSim 和 HoloOcean 能否用于演示和测试（2026-10-05）

用户的问题（原话）："其他组员想用Lotussim或者holoocean做演示/测试，你也研究一下？"

**做法：** 只做调研，没有下载、安装或运行任何东西。
- 两个仿真器各由一路查官方仓库、文档、论文和更新记录；
- 一路查同类仿真器；
- 一路查它们和我们代码的接口怎么对接；
- 最后综合，再由三路逐条反驳核对（32 条，27 条确认，5 条修正，修正已并入下文）。

## 结论

- **两个都是真实、仍在维护的海洋机器人仿真器，但都不模拟滑行艇。**
  - 它们没有船体在高速下被水托起的升力，没有落水拍击，也没有喷泵。
  - 我们的船在 30 节时完全靠滑行升力支撑，所以在它们里面跑出来的冲击、纵摇、升沉不能代表我们的船。
- **能用来做的事：** 好看的演示画面；检查我们的软件能否在机器人通信框架（ROS 2）里跑通，即接口、时延、传感器管线。
- **不能用来做的事：**
  - 判断控制器是否安全、是否够快；
  - 导师要的一维单浪实验；
  - 给误差模型生成训练数据。
- **我们自己的条件更好。** 我们自己的高保真仿真加上已有的网页三维查看器，对这条船比它们更真实；查看器画的浪就是仿真里船实际遇到的浪。

## LOTUSim

- **是什么：** 法国海军集团（Naval Group）与 CNRS、IMT Atlantique 开发（github.com/naval-group/LOTUSim）。论文 Buche 等，"LOTUSim: Multi-Domain Simulator for Marine Robotics"，IROS 2026（arXiv:2607.03072）。开源许可 EPL-2.0。
  - 不要和同名的公交电车模拟游戏 LOTUS-Simulator 混淆。
- **结构：** 用 Gazebo 和 ROS 2 管场景和通信。船的运动由单独的物理程序 xdyn（海军集团的版本叫 lxdyn）计算：
  - 刚体六自由度运动；
  - 按真实湿表面积分的浮力；
  - 未受扰动波浪的压力力；
  - 可选的线性绕射和辐射；
  - 常规的操纵、阻力、螺旋桨和舵模型。

  可选用 Unity 渲染三维画面。
- **波浪：** 只有线性波，可以用标准波谱、方向分布和随机种子生成。原理上可以通过网络接口喂入我们自己的波浪分量。
- **船模：**
  - 都标为原型阶段；
  - 小艇模型是占位用的立方体，没有推进器，没有标定；
  - 唯一标定过的是 142 米的驱逐舰船型。
- **可重复性：** 设计上每次运行的顺序和时序都带随机性，结果不能逐次重复。
- **近期错误：** Gazebo 与 xdyn 之间的桥接曾把姿态四元数的两个分量对调（转向显示成横摇或纵摇），还把步长当成了绝对时间发出去（波浪力在时间上冻结）。修正于 2026-09-24 随 PR #82 合入主干（PR #74、#54 未合并而关闭）。在此之前带波浪的结果都可疑。
- **画面和物理不同步：** Unity 的水面与物理里的浪不同步（各走各的时钟，平铺重复），画面只在统计上像物理里的海况。它预设的"三级海况"是有义波高 1.5 米、周期 3 秒，比我们的评估海况陡得多。
- **平台：**
  - 原生支持 Linux 和 macOS。
  - Windows 上的 Nix 安装方式要在 WSL2（Windows 自带的 Linux 虚拟机）里跑 NixOS-WSL，说明里建议给虚拟机 16 GB 内存，等于我们笔记本的全部内存。
  - 另有容器镜像，但没写 Windows 怎么用，大概也要经过 WSL2。
  - 它追求实时运行，带学习模型的控制器每步要 3–6 秒，跟不上。

## HoloOcean

- **是什么：** 杨百翰大学 FRoSt 实验室开发，基于虚幻引擎（Unreal Engine 5.3）。主要面向水下机器人和声呐、相机等传感器仿真。论文 Potokar 等，ICRA 2022；Romrell 等，"A Preview of HoloOcean 2.0"，arXiv:2510.06160。
- **水面船：**
  - 只有一个"带两个推进器的简单水面船"（类似 WAM-V 双体船），浮力用游戏式的采样点或网格计算，文档自己提醒可能不符合真实浮力。
  - 可选的方程模型是 2 米长、约 6 节的 Otter 双体船，没有波浪力，而且和画面上的模型没有联动。
- **波浪：**
  - 已发布的 2.3.0 版水面是平的。
  - 开发分支的 2.4.0（2026-09-04）加了快速傅里叶变换生成的波浪，波浪会影响水面船的浮力。
  - 只能按"风速"或 0–9 级海况预设，或者调各层频带的幅度、截止波长等参数。没有有义波高和周期的直接输入，没有标准波谱，没有随机种子或相位控制，所以不能让它的浪等于我们的浪。
  - 没有传感器能直接读浪高。
- **接口：**
  - Python 接口，仿真器每一帧都等 Python 这边（锁步），所以慢的控制器也能接。
  - 有 ROS 2 桥。
  - 可以每帧直接设定船的位置和姿态，因此能只当渲染器用，播放我们录下的轨迹。
- **许可和平台：**
  - 自家代码是 MIT 许可，另需接受虚幻引擎许可协议；每个用户都要把 GitHub 账号绑定 Epic 账号才能拿到代码。
  - 支持 Windows 和 Linux。推荐配置（文档说没有已知最低要求）：独立显卡、8 GB 以上内存、四核处理器。我们的显卡够，内存是瓶颈，要单独运行。
  - Windows 上窗口不能隐藏。
  - 自己做船型或场景需要虚幻编辑器和 Visual Studio。

## 四种用途

| 用途 | 结论 |
|---|---|
| 演示 | 可以。最省事是用 HoloOcean 播放我们录下的轨迹，约几天，但画面里的浪不是船实际遇到的浪；要让浪对上，得导入船型、换掉水面，要会虚幻引擎的人做几周。LOTUSim 的 Unity 渲染器同理 |
| 独立测试控制器 | 只能做软件接口测试（ROS 2 消息、时延、传感器），外加低速近似排水状态下的粗略检查。不能测性能和安全：它们没有拍击，高速下的纵摇、升沉也不对。若把我们的力接进去，物理对了，但就不再独立 |
| 一维单浪实验 | 不合适。直接在我们仓库里用 Python 写，推力和阻力取自我们的高保真船，两边结果才能对上；我们的查看器可以显示单个长峰浪 |
| 误差模型训练数据 | 有害。会学到"我们的船和一个不会滑行的游戏物理船"之间的差别；LOTUSim 还不能逐次重复 |

**限值的迁移：** 3 g 和 7 g 的冲击限值来自船级社和行业标准，可以迁移到别的仿真器。但我们乘的系数 2 是专门修正我们仿真低估冲击的，换仿真器必须重新标定。而这两个仿真器根本没有拍击，没有可用的冲击量。

**真正独立的物理检查：** 应该用公开的滑行艇拖曳水池数据（如 Fridsma 的规则顶浪试验、Begovic 等）比对我们的高保真船，有集群的话再加几个计算流体力学算例。商用滑行艇程序与我们同属切片方法，不算完全独立。

## 建议

1. **演示：** 先用我们自己的网页查看器，改成显示这条滑行艇（新的导出脚本、按 48 个截面生成船体网格、调整颜色刻度和告警线等）。已有 34 个闭环任务的完整录制，不用重跑。
   - 要逼真场景（港口、相机或激光雷达画面）时，再用 HoloOcean 播放录好的轨迹，并标明"这是我们仿真的回放"。
2. **测试：** 只拿它们做软件接口测试，最好放在 Linux 机器或容器里，不要和训练抢这台笔记本的内存。
3. **不要从中得出的结论：**
   - 控制器在它们里面"通过"，不说明在我们的船上安全或快；
   - 画面更好看不等于更准；
   - 它们的"三级海况"不是我们的海况。

## 补充：我们自己做能否达到它们的画面质量（2026-10-05）

**做法：** 取一次真实闭环航行的同一时刻：只用简化模型的约束 MPC，种子 3，顶浪，约 27 节，飞出浪顶约 0.8 秒后以 11 g 落水，是这类任务里最重的一次。在三种方式下画同一画面：
- 现有查看器；
- 新写的网页实时原型（`viewer/proto_web.html`，three.js）；
- Blender 离线渲染（`viewer/proto_blender/render.py`，Cycles 引擎）。

其中浪用这次航行自己的 120 个波浪分量，船的位置姿态用每 0.02 秒的记录，船底形状用仿真里的截面。对比图 `viewer/proto_compare.png`，视频 `viewer/proto_blender/clip_cycles.mp4`。

**结果：**
- **Blender：** 在跟拍距离上，水面、天光和倒影接近照片；每帧渲染约 5 秒（1280×720）。露馅的地方都是美术问题：
  - 船是仿真用的简化船型，直舷、钝头，看着像澡盆；
  - 天空无云；
  - 白浪和落水溅起的水花是手调的；
  - 没有船自己兴起的波浪，因为仿真里不算这个。
- **网页原型：** 在这台笔记本上实时运行，约每秒 60–80 帧。比现有查看器好得多，像一款不错的游戏，但水面有条纹、倒影有锯齿，到不了照片级。
- **它们的画质从哪来：** HoloOcean、LOTUSim 的画质来自引擎的光照、统计生成的水面和建模好的素材，不来自它们的物理。它们都没有说明画面里的浪等于物理里的浪；我们的两种原型里，近处的浪和船的运动都是仿真中真实发生的。网页原型在镜头约 30 米内精确，更远处省略了短波；Blender 约 90 米内精确。

**路线和工作量（估计）：**

| 路线 | 能达到什么 | 工作量 |
|---|---|---|
| Blender 出演示视频 | 达到并在"画面等于仿真"上超过它们；不能交互；1 分钟视频需渲染一夜 | 约 2–3 周：真实船体模型、云、船行波、水花、批量出片 |
| 网页查看器日常交互回放 | 好看的实时画面，达不到虚幻引擎的光照 | 约 2–3 周到可演示 |
| 自己用虚幻引擎 5 | 与 HoloOcean 同一引擎，原理上同等画质 | 约 2–4 周，需要自定义水面材质输入我们的波浪；官方建议 32 GB 内存，这台机器不够 |
| Unity HDRP | 内置水面只能按风速等参数生成，不能直接用我们的波浪 | 约 2–3 周加安装，好用的第三方海面插件收费 |

**建议：**
- 演示视频用 Blender，第一步先做一个像样的船体模型，这是最大的画面提升。
- 日常交互回放用网页查看器。
- 现在不转虚幻引擎或 Unity。
- 无论哪种路线，都把"只是视觉"的部分标出来（白浪、水花、天空、细小波纹）。
